## Threshold (SLO) тохируулан хийсэн хэмжилт

5 VU-тэй туршилтын p95 latency нь 310 мс гэдгээс SLO threshold-оо $310 \cdot 1.5=465 \approx 450$ мс гэж тохируулсан.
30 VU ажиллуулж хэмжихэд `p(95)=236.79ms, rate=0.00%` үр дүн гарч, тэнцсэн.
```

    http_req_duration
    ✓ 'p(95)<450' p(95)=236.79ms

    http_req_failed
    ✓ 'rate<0.01' rate=0.00%
```

Харин latency threshold-оо 50мс гэж тохируулж, албаар унагахад дараах үр дүн гарсан:

## Дүгнэлт

VU-ийн тоог нэмэгдүүлэхэд throughput нь дагаж өссөн. 100 VU хүрэх үед p95 latency нь 381 мс хүрсэн нь ачаалал ихсэн үед серверийн хариу үйлдлийн хурд багасч байгааг харуулж байна. Гэхдээ error rate 0% байсан нь `test.k6.io` сервер нь ачаалал даах чадвартайг харуулж байна.

SLO latency threshold-ийг 5 VU-тэй туршилтын p95-ыг 1.5-аар үржүүлэн бодож тодорхойлсон. Энэ threshold туршилтын үр дүнд хангагдсан. Энэ SLO-г албаар хүндрүүлэхэд k6 нь үр дүнгийн `THRESHOLD` хэсэгт `http_req_duration` буюу latency хэмжилтэд унасан болохыг харуулж, мөн error buffer-д `thresholds on metrics 'http_req_duration' have been crossed` гэсэн алдаа хэвлэж байна.
